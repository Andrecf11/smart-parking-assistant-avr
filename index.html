  • Introdução

Início


Este relatório foi elaborado como parte da cadeira de Laboratórios de Sistemas do primeiro semestre do terceiro ano da Licenciatura em Engenharia Eletrotécnica e de Computadores no Instituto Superior de Engenharia do Porto. O propósito deste projeto é criar um sistema que ajude no estacionamento automóvel para tornar as manobras mais fáceis e reduzir os danos nos veículos.

O desenvolvimento de um sistema de assistência ao estacionamento visa solucionar um desafio comum enfrentado pelos motoristas: as limitações de visão ao manobrar o veículo no dia-a-dia. Mesmo com o uso dos retrovisores para auxílio visual há áreas com visibilidade reduzida tanto à frente quanto atrás do carro que aumentam o risco de colisões acidentais com obstáculos. Esse sistema foi criado com o intuito de minimizar consideravelmente tais riscos ao implementar sensores que detectam objetos próximos e alertas sonoros graduais juntamente com feedback visual em uma tela para promover maior segurança e precisão durante as manobras.

O projeto também leva em conta a adaptação para veículos mais antigos, que muitas vezes não possuem tecnologias avançadas de auxílio ao estacionamento, o que faz desta solução uma solução vantajosa tanto para modelos antigos quanto para os mais recentes. Portanto, o sistema pode ser uma alternativa viável para reduzir os gastos relacionados a reparos, melhorar a segurança e proporcionar uma experiência de direção mais segura e confiável.

  • Arquitetura

Início



O diagrama de blocos abaixo representa a arquitetura do sistema de assistência ao estacionamento, demonstrando a interação entre os elementos principais do projeto. O microcontrolador Atmega168 é o núcleo do sistema, encarregado de processar as entradas e gerenciar as saídas.
O sistema é alimentado por uma pilha de 9V, que é ajustada para 5V por meio de um regulador de tensão. Esta tensão estabilizada fornece energia ao microcontrolador e aos periféricos, assegurando o funcionamento seguro e eficaz de todo o sistema.
Os sensores ultrassónicos (Sonar1 e Sonar2) são fundamentais para identificar obstáculos, transmitindo informações ao microcontrolador. Esses sensores analisam a proximidade de objetos, fornecendo informações fundamentais para as decisões do condutor. A partir das informações dos sensores, o microcontrolador envia od dados para os atuadores, estes que são os LEDs, o buzzer e o LCD. O Atmega168 foi programado e controlado com o programador USBasp, o que possibilitou a aplicação do firmware indispensável para o funcionamento do sistema.

Em síntese, esta estrutura demonstra a combinação eficaz de elementos de hardware e software para estabelecer um sistema funcional e de fácil acesso, que pode aprimorar consideravelmente a segurança e a exatidão nas manobras de estacionamento.

Atmega168: Optámos por usar este microcontrolador, que será responsável por executar o código programado para controlar os outros componentes.

Caracteristicas:
Microcontrolador de 8 bits.
28 pinos.
Alto desempenho e baixo consumo de energia.
Família AVR.
32 Kbytes de memória programável, 1 Kbytes de memória EEPROM, 2 Kbytes de memória SRAM.
3 timers/counters (dois de 8 bits e um de 16 bits).
6 canais de PWM.
1 conversor analógico-digital (ADC) com 8 canais e 10 bits de resolução.

USBasp: Foi utilizado para programar o microcontrolador Atmega168 o USBasp.

Caracteristicas:
Funciona em diversos sistemas operacionais: Linux, Mac OS X e Windows (32 e 64 Bits).
Permite a leitura ou escrita na EEPROM do microcontrolador, firmware, fuse bits e lock bits.
Velocidade de programação é maior que 5kBytes/seg.
Opção de modo lento SCK para alvos com baixo clock (<1.5Mhz).
Interface ISP 10 pinos.
Dimensões: 7cm x 2cm.

LEDs: Os LEDs foram utilizados no projeto como indicadores visuais de checkpoints correspondentes às distâncias detetadas pelo sistema de sensores. Para proteger os LEDs e garantir o seu funcionamento adequado, utilizámos resistências apropriadas, dimensionadas com base na tensão de operação e corrente máxima suportada pelos LEDs.

Caracteristicas:
Diâmetro do díodo dos Leds: 3mm.

Sensor HC-SR04: Este sensor é responsável por medir distâncias instantâneas, envia pulsos ultrassónicos e captura o tempo de retorno do eco. Os valores medidos são convertidos em sinais que podem ser processados pelo microcontrolador.


Caracteristicas:
Tensão de Funcionamento: DC 5 V.
Corrente de Funcionamento: 15 mA.
Frequência de Funcionamento: 40 Hz.
Alcance Máximo: 4 m.
Alcance Mínimo: 2 cm.
Ângulo de Medição: 15 graus.
Sinal de Entrada do Trigger: Pulso TTL de 10 µs.
Sinal de Saída do Echo: Sinal de nível TTL proporcional à distância medida.
Dimensões: 45 x 20 x 15 mm.

Buzzer: Foi utilizado um buzzer passivo para produzir um sinal sonoro cuja frequência aumenta à medida que a distância diminui, permitindo que o utilizador identifique rapidamente a proximidade de um obstáculo ou alvo.

Caracteristicas:
Tensão Nominal: 3 a 5 V.
Saída de Som a 10 cm : ≥ 85 dB.
Faixa de Frequência: 50 ~ 14.000 Hz.
Frequência de Ressonância: 2048 Hz.
Temperatura de Operação: -20 a 60°C.

Display LCD 20x4 Backlight 017-1396: Este display serviu para poder exibir os valores de distância frontal e traseira medida pelos sensores.

Caracteristicas:
Controlador LCD: HD44780
Protocolo Comunicação: I2C

Controlo de contraste através de potenciómetro

1. Definições de Pinos e Configuração Inicial

O programa define pinos no microcontrolador para o controle dos sensores ultrassônicos, LEDs e o display LCD. As macros são usadas para facilitar a leitura do código.

Sensores ultrassônicos:
TRIG_F e TRIG_T: São configurados como saídas para enviar os pulsos de controle.
ECHO_F e ECHO_T: São configurados como entradas para receber os sinais refletidos pelo sensor.

LEDs:
Seis LEDs indicam a faixa de distância traseira e frontal: até 20 cm, 40 cm e 60 cm.
PORTC e PORTB são usados para controlar os LEDs.

Display:
Conexão via interface I2C, com endereço padrão definido como 0x27.

2. Configuração dos Pinos

A função init_pins() configura os pinos necessários: Essa configuração é essencial para controlar corretamente o hardware conectado ao microcontrolador.
Nesta etapa inicializamos tambem o timer0 para o buzzer, criando uma variável para a frequência da onda PWM pois esta vai ser útil.

3. Sensores Ultrassónicos

Os sensores utilizam sinais de ultrassom para medir distâncias. Para isso:
Um pulso de 10 µs é enviado no pino TRIG para iniciar a medição.
O pino ECHO recebe o pulso que foi refletido, que é proporcional ao tempo que o som levou para ir e voltar.

A função trigger_pulse() envia o pulso de controlo no pino trigger: Utilizou-se esta formatação para que fosse possivel defenir o nivel lógico alto ou baixo adequado ao nosso fim.

4. Cálculo do Pulso de ECHO

A função calcular_echo_pulse() mede o tempo em que o pino ECHO permanece em nível alto, que é proporcional à distância do objeto.

Configuração do Timer 2:
O Timer 2 do AVR é usado para medir o tempo do pulso.
Configuração: Prescaler de 64.
Isso significa que cada vez que o contador do timer é incrementado representa 32 µs. O timer conta até 255 (8 bits), o que equivale a um tempo máximo de 255 × 32 µs = 8.16 ms. Este valor é suficiente para medir distâncias de até 1.4 metros, calculado atravéz da velocidade do som, o que é suficiente para o ideal do nosso projeto.

5. Cálculo da Distância

A distância é calculada com base no tempo medido pelo Timer 2.

6. Interface I2C e Display LCD

O display LCD é controlado via interface I2C. As funções principais incluem:
i2c_init(): Inicializa o módulo I2C.
lcd_send_command() e lcd_send_data(): Envia comandos e dados ao LCD.
lcd_print(): Exibe strings no display.

O LCD, no nosso projeto, é usado para mostrar as distâncias medidas pelos sensores, sendo atualizadas em tempo real.

7. Controlo do buzzer

Para que o buzzer consiga alertar o condutor da proximidade de um obstáculo, decidimos aumentar a frequência da onda à medida que a distância fosse menor.

8. Função main:

Chamada das funções para a main
No início da função main, que é o coração do nosso progama, chamamos as funções de inicialização para configurar o hardware conectado ao microcontrolador: Estas chamadas grantem que:

Variáveis Locais
Foram criadas variáveis para armazenar os valores necessários ao longo do programa: O buffer que é usado para montar strings formatadas com as informações de distância. O sensor_atual alterna entre os sensores ultrassónicos. Ciclo While
O programa entra em um loop para realizar medições contínuas. Dentro deste loop, há várias etapas:

Medição da distância
A medição é alternada entre os sensores frontal e traseiro. Isso é controlado pela variável sensor_atual:

Se o sensor atual for o frontal (sensor_atual == 0), a medição ocorre com os pinos TRIG_F e ECHO_F. Se o sensor atual for o traseiro (sensor_atual == 1), a lógica é semelhante, mas usando os pinos TRIG_T e ECHO_T. Atualização do Display LCD
Depois que a distância é calculada, o programa exibe o valor no LCD. Controlo dos LEDs
Os LEDs são usados para indicar visualmente a faixa de distância medida pelo sensor frontal e traseiro. O programa apaga todos os LEDs antes de verificar em qual faixa a distância se encontra.
EScolha do sensor
O programa indentifica qual é o sensor que está a ler uma menor distância e chama a função para a alteração da frequência selecionando o sensor identificado. Alternância entre sensores
Ao final de cada interação, o programa alterna o sensor para a próxima leitura. Isso é feito invertendo o valor de sensor_atual: Atraso para Estabilizar

  • Conclusões

Início



Após a conclusão do projeto verificamos que produzimos um projeto funcional e dentro dos objetivos, embora enfrentando alguns desafios e dificuldades. Uma das principais dificuldades foi a implementação dos sensores ultrassónicos, pois foi necessário ajustar os tempos de resposta e calibrar os sensores para obter valores o mais precisos possível. Em várias ocasiões, as leituras dos sensores não eram fiáveis, levando-nos a realizar uma revisão sobre a calibração e configuração dos mesmos.

Para melhorar este projeto no futuro, poderíamos considerar:
Uso de sensores diferentes, como câmeras ou sensores infravermelhos, para melhorar a precisão.
Melhorias no feedback visual e sonoro, como a utilização de displays gráficos mais avançados.

Outra das melhorias, e que fazia parte das ideias iníciais, era colocar um maior número de sensores em locais estratégicos para que pudesse haver mais leituras do que está a ocorrer perto do carro, tornando ainda mais difícil haver uma colisão, que é o nosso objetivo principal. No entanto, devido ao curto espaço de tempo, não foi possível implentar e aperfeiçoar alguns aspetos e resolver alguns possíveis problemas que podessem, eventualmente, aparecer.
